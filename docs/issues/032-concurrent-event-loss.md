## 与重实现目标的关系

本条确认的是 Evo 当前代码的具体行为，不证明重新实现的服务也有同样问题，不作为先修旧代码的任务。

它对应的新服务设计关注点是：并发时成功确认的任务事件是否真的完整保留。关联 [EVO-001](001-trajectory-recording.md)。归入实现问题不表示可以忽略这一正确性要求。

## 当前情况

record_event() 先读整个任务文件，在内存里添加事件，然后把整份任务写回。

## 不合理的地方

两个执行器先后读到同一份旧内容时，各自新增的事件会互相覆盖。不同 event_id 也不能避免。

## 影响

Logmind 多个执行器或任务分支汇入同一 Evo 任务时，已确认成功记录的调用仍可能丢失。

## 代码位置

- [evoontology/workflow.py](../../evoontology/workflow.py#L191)：`ProjectWorkflow.record_event`，第 191 行。读任务文件。
- [evoontology/workflow.py](../../evoontology/workflow.py#L206)：`事件追加与保存`，第 206 行。读改写没有跨调用保护。

## 核对依据与边界

用两个线程固定“两次读取后再依次写入”的交错。两次调用均返回 recorded，最终文件只有一个事件。测试串行化了文件写入，因此不依赖临时文件碰撞。条件是多个执行器共享同一任务；单个 stdio 顺序调用不触发。
