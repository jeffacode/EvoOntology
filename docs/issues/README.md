# 面向 Logmind 语义层重实现的问题清单

目标：参考 Evo 的方法和源码，重新实现语义层服务供 Logmind 使用。**本目录不是“先修完 Evo 再接入”的任务表。**

2026-10-23 重整，共保留 37 条证据记录，原编号和文件路径不变。只整理问题、适用范围和代码依据，不写解决方案。论文对应关系见[对照文档](../paper-code-comparison.md)。

## 分类口径

| 分类 | 数量 | 对当前目标的意义 |
| --- | ---: | --- |
| 核心设计议题 | 15 | 换一套实现仍然要明确的语义、版本、评测和服务边界；其中有些需求已经明确，缺的是完整边界 |
| Evo 当前实现问题 | 14 | 旧代码中已发现的具体错误；不自动成为新服务的 bug 或旧代码修复任务 |
| Logmind 客户端问题 | 2 | 问题在宿主侧，重写语义服务不会自动消除；是否触发取决于接入行为 |
| 原包复用限制 | 2 | 直接复用旧入口或展示组件时才成立，不是重实现的前置任务 |
| 论文与 benchmark 参考 | 4 | 用于研究复现或复用对应评测组件，不直接等于业务发布要求 |

“核心”表示需要作出设计判断，不表示论文设计有错，也不表示新服务已缺少这些能力。“实现问题”也不表示不重要：例如旧评分发布、并发丢记录，背后的正确性要求仍然适用。每条正文都写明了这层关系。

旧 notes 中有方案讨论和早期“直接接入 Evo”的表述；以本次重实现目标为准。本目录不把历史方案自动变成已确定需求。

## 每份问题文档的统一结构

1. **基本信息**：证据类型、当前分类、处理定位和核对版本。
2. **与重实现目标的关系**：哪些是新服务设计议题，哪些只是原实现现象，以及适用条件。
3. **当前情况**：已核对的源码行为。
4. **不合理的地方**：具体问题；能力限制不直接等同于普遍设计错误。
5. **影响**：对应场景下的后果。
6. **代码位置**：原证据的文件、函数和行号。
7. **核对依据与边界**：复现范围及没有验证的部分。

编号和文件名保持不变；核心议题的标题已改为设计视角，原问题标题保留在“基本信息”。每条都保留代码依据。行号对应当时核对的源码，不代表已经检查了尚未实现的新服务。
